Реализован серверный рынок, который позволяет нескольким клиентам работать с одним экземпляром Market через HTTP.



Пока что все клиенты фактически торгуют с одного аккаунта.

Пока что все состояние хранится в памяти.







\## Реализовано



Решение разделено на проекты



&#x20;- exchange-simulator - торговое ядро

&#x20;- exchange-simulator.Contracts - сетевые DTO

&#x20;- exchange-simulator.Server - ASP.NET Core сервер

&#x20;- exchange-simulator.Clients - независимый консольный HTTP-клиент

&#x20;- exchange-simulator.Tests - доменные unit тесты и сетевые интеграционные тесты



Сервер является единственным владельцем движка учета и обработки клиентов и их заявок.

Рынок запускается вместе с сервером и продолжает выполнять шаги ботов независимо от подключения клиентов.







\## HTTP API



Публичные запросы позволяют получить

&#x20;- торговый инструмент

&#x20;- состояние рынка и оценочную цену

&#x20;- текущий стакан заявок

&#x20;- последние сделки



Персональные запросы позволяют получить

&#x20;- состояние счета

&#x20;- собственные активные заявки



Торговые команды позволяют

&#x20;- разместить заявку

&#x20;- отменить активный остаток заявки







\## Участник



На текущем этапе все внешние клиенты используют один тестовый счет.



Перед отменой сервер проверяет принадлежность заявки к этому общему счету.



Попытка отменить и чужую, и неопознанную заявку вернет одинаковый результат с кодом 404.







\## Сетевые контракты



Запросы и ответы передаются в JSON



Enum передаются строками в camelCase, числовые значения отклоняются.



Цены и деньги предаются как decimal, обычные кол-ва как long, НО

агрегированный объем уровня стакана передается строкой,

чтобы не зависеть от ограничений числовых типов JSON и сохранить точное значение, потенциально превышающее long.





Ошибки возвращаются отдельным non-2xx ответом

с полями code (стабильный код ошибки) и message  (сообщение для пользователя)



Используются статусы 400, 404, 405, 409, 415, 500.







\## Консольный HTTP-клиент



Команды можно узнать с помощью help



Клиент получает все состояние только через HTTP и не имеет никакого доступа к торговому движку.



Тайм-аут одного запроса 5 сек.



Торговые команды автоматически не повторяются.



Если соединение прервалось до получения ответа, результат считается неизвестным, поэтому клиент повторно читает счет, заявки и сделки, но не отправляет команду еще раз.
